# Character choice UI review

September 27 consolidation: the [shared hierarchy and composition](widget-consistency-2026-09-27.md) now provide one Keystone editor and one catalogue interaction across Trait, Feat, Technique, Weapon and Enhancement choices. Ordinary and granted Equipment/Techniques share domain presentation; Technique acquisition supports compact names and expanded rules with named checkbox controls. Enhancement follow-up fields share the same component. Bond labels and option-group disclosure associations are connected. The earlier [survey](widget-consistency-survey-2026-09-27.md) records the before-state; remaining rank/form/navigation work stays within the wider UI-system step.

September 23 contrast follow-up: shared status-pill values now inherit success/danger colors, errors pair readable text/backgrounds, and unavailable-option explanations use readable muted text. Shared accent buttons and sheet labels, placeholders, metadata and Elementalist headings also received cross-theme repairs. See [the measured contrast review](color-contrast-review-2026-09-23.md) for scope and verification.

September 23 grant-reference follow-up: the former feature-option gap is closed by shared `rule-details.js` disclosures. Unselected Class/Feat options now expose named grants, including all four Transformed Instinct reactions. Fixed Class/Origin features and expanded Feat/Trait candidates share the component; the September 27 acceptance removes separate selected-result duplicates. Techniques, Traits, Feats, Features, Weapons and Enhancements support full-text references, with nested associated rules, scoped keys and explicit missing/ambiguous notices. Browsing is independent of selection and preserves expansion across rerenders/cancellation. Prose without a structured reference remains prose, and unsupported mechanics remain unsupported. The read-only sheet's existing full cards are unchanged. Seven controlled regressions and real local Instinct/Trait keyboard and cancellation checks pass; see [status.md](status.md).

Reviewed September 22, 2026, against the user's requests for eligible-only choices, compact names/expanded full text, conditional prerequisite lines, and controls inside their granting features. This is an implementation inventory, not authorization to change game rules or publish data.

September 27 manual acceptance supersedes the earlier selected-description policy: all shared catalogue pickers now use selected names/checkmarks in compact mode and full rules only within expanded options. Repeated selected-description blocks are removed for Traits, Feats, ordinary/granted Techniques, Weapons and Enhancements. Nested Feat choices and Enhancement fields remain visible; read-only equipment can still expand. The user accepted Keystone appearance, text limiting/saving, and Feat/Technique expansion; other manual scenarios remain open.

| Location | Finding and disposition |
| --- | --- |
| Class and archetype feat grants | Already filtered by grant type/category/level and character eligibility in both views. Compact names, expanded full descriptions, source-owned placement and hidden satisfied prerequisites are implemented. |
| Trait choices in Class features, selected feature options and feats | Corrected: ineligible choices are omitted rather than shown disabled. Compact names and expanded full descriptions/rank notes use the same Rules result. Selection/cancellation retains expansion and focus. |
| Origin Trait grants | The same filtering and expansion apply. The formerly separate whole-character Trait summary is replaced by controls inside each granting Origin feature. Direct Origin grants remain within the Origin summary. Inactive future features and reference-only entries create no widget. |
| Feature and feat option cards | Satisfied prerequisite lines are already omitted. Unavailable cards are hidden by default and can be deliberately revealed with Show Unavailable Options. Their full text is shown, and groups can collapse; this is an explicit browsing control, separate from eligible-only acquisition dropdowns. A names-only selection view would be additional UI work. |
| Granted Technique choices | Corrected: names-only dropdowns and expanded full descriptions use the same eligible options. Current saved choices stay inspectable; expansion, cancellation and selection focus survive widget recreation. |
| Granted Weapon and Enhancement choices | Corrected: shared Weapon Rules apply readiness and rank filtering; enhancement compatibility remains shared. Both offer names-only dropdowns and full-text browsing, retaining selected names, expandable rules and the original granting source. |
| Equipment page | The same expandable catalogue serves Add Weapon, weapon-base and enhancement selectors. Readiness/rank/compatibility filters remain Rules-owned, and existing owned items remain inspectable. Granted weapon bases/ranks remain owned by their feature; optional enhancements can be edited in Equipment through the canonical grant answer, while automatic enhancements stay protected. |
| Technique catalogue page | Shared compact/expanded named checkbox rows are grouped by rank and individual qualifying skills. Multi-skill Techniques join each applicable skill group, alongside exclusive Techniques; they retain one stable answer and synchronized checkmarks, counting once. Group membership, search and skill summaries read parsed routes rather than a combined skill label. Selected checkmarks suffice in compact mode; full rules appear once within expanded options. Current schema-3 ordinary choices pass access and prerequisite Rules; automatic/source-owned entries remain visible as acquired items. Multi-selection intentionally uses checkboxes rather than a single-choice dropdown. |
| Class and Origin selection | Corrected: unavailable acquisition alternatives are hidden, including Coming Soon classes. Existing saved choices remain visible for inspection. Dropdowns show names without readiness suffixes. |
| Character sheet | Read-only acquired/reference cards are not acquisition pickers. Full Trait descriptions and reference status remain useful here; the builder's collapsed-choice view should not remove them. |

Future UI work should review all mounting pages whenever a shared choice behavior changes. Preserve the same Rules and session-command boundaries; view controls must not introduce new ownership, eligibility, saved fields or automatic gameplay state.
